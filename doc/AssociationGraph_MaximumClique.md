# Association Graph と最大クリークによる最大共通部分グラフ検出

このドキュメントでは、2 つの操作列から構成されるグラフの最大共通部分を求めるために導入した Association Graph と最大クリーク探索アルゴリズムについて説明します。あわせて実装済みのテストの手順も示します。

## Association Graph とは

2 つのグラフ \(G_A\) と \(G_B\) に対し、頂点の潜在的な対応をすべて列挙して作る無向グラフを **Association Graph** と呼びます。各ノードは元のグラフの頂点のペア \((a_i, b_j)\) を表し、エッジはその 2 つのペアが同時にマッピング可能である場合に張られます。つまり、エッジがあるときは元グラフでの依存関係が両方同じ向きで存在する、または両方無いことを意味します。

Association Graph を構成することで、対応可能な頂点集合を最大クリーク問題として解けるようになります。

## 最大クリーク探索

Association Graph の最大クリークは、同時に選択可能な頂点ペアの最大集合を与えます。この集合が両グラフの最大共通部分写像に相当します。実装では Bron–Kerbosch 法に近い再帰的バックトラックを用いた簡易版を実装しています。

1. 可能な頂点集合 \(P\) から 1 つ選び、再帰的に探索を進めます。
2. \(P\) と排除集合 \(X\) の両方が空になったとき、現在の部分集合がクリークとなります。
3. より大きなクリークが見つかれば結果を更新します。

得られたクリークに含まれない頂点は、それぞれのグラフに固有の頂点として差分に分類します。

## 詳細構造グラフを用いた拡張

`semantic_common_subgraph` 関数では、各操作列から `build_detailed_structure_graph` を使って
`DetailedNode` ベースのグラフを構築します。Association Graph もこれらのノードのペアで
作成されるため、`AddNode` や `AddEdge` が参照する `NodeId` が異なっていても同一操作とみな
すことができます。最大クリークに含まれた `NodeId` のペアで値が異なるものは
`Hole::Ref` として結果に保持され、対応する操作写像と共に返されます。

## テスト手順

tests/max_common_subgraph_tests.rs では次の 2 パターンを確認しています。

1. **完全一致する場合**
    - `append_ops_original` と `append_ops_b` で生成した操作列を入力します。前者は `Node` ノードとリテラル `0`、後者は `Node` ノードとリテラル `3` を含みます。
    - 各操作列から依存グラフを構築し、潜在的に対応する操作の組を Association Graph に登録します。ノード追加のマッチングでは `is_literal` を比較し、リテラルノードの場合は値の違いを許容します。生成されたノード同士は ID が異なっていても対応候補に含まれます。
    - 最大クリーク探索の結果、`Node` の追加と `val` 辺の追加が対応し、リテラル値の違いや `next` 辺の起点違いは差分として検出されます。
2. **差分が存在する場合**
    - `prepend_ops_original` は変数追加を含む 5 操作、`insert_after_ops_original` は辺の書き換えを含む 5 操作を生成します。
    - Association Graph を構築後、共通部分に対応する 3 操作がクリークとして選ばれます。`AddVariable` と `EditEdgeReference` はどちらかのグラフにしか現れないため差分となります。

以上のテストにより、最大共通部分グラフの取得と差分抽出の両方が期待通り機能することを保証しています。
