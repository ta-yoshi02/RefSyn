# ランダム操作列による検証

この資料は、2026-10-16 に追加したテストの目的、判定方法、再現手順を記す。
従来のテストの一覧は [TESTS.md](TESTS.md) を参照する。

## 検査対象と判定方法

| 対象 | 検査する性質 | 期待結果の作り方 | 規模 |
| --- | --- | --- | --- |
| 操作の読込みと正規化 | 操作列の各段階で、正規化後の生成と書込みが期待状態を再現する | 操作列を生成すると同時に、テスト側のオブジェクト表を直接更新する | 64 seed × 48段階 = 3,072比較と、空の操作列64比較 |
| 正規化の拒否条件 | 記録された旧参照が現在のフィールドと異なる操作を拒否する | 有効な操作列の旧参照を、別の既知オブジェクトへ差し替える | 64件 |
| 合成された5メソッド | 混合した連続呼出しの各段階で、参照実装と状態と戻り値が一致する | 保存された `target_program.js` の各メソッドを、別のオブジェクト群で実行する | 288系列 × 50呼出し = 14,400比較 |
| 比較器自身 | 正しい候補を受理し、既知の誤りを含む候補を拒否する | 意図的に壊した候補と正例を与える | Node の15テスト。うち誤候補9件 |

正規化のテストは、`tests/operation_graph_randomized_tests.rs` にある Rust の `#[test]` 2件である。
混合呼出しは `tests/whole_method_validation_tests.rs` の `#[tokio::test]` 1件、比較器の検査は同ファイルの `#[test]` 1件から起動する。
標準の `cargo test --locked` と、既存の親 CI の Rust tests で実行される。
テスト関数の数と、関数内で比較する入力や操作の数は異なる。

## 操作の正規化で確かめること

操作列を作る側は、Kanon 形式の JSON と、その操作後に期待するオブジェクト表を同時に作る。
期待状態の計算には本体の読込み処理や正規化処理を使わない。
検査対象の経路は `demonstration::read` → `operation_graph::build` である。
出力された操作グラフの生成頂点と書込み列をテスト側で実行し、オブジェクト表全体と戻り値を比較する。

各系列は既存オブジェクト5個から始まる。
初期状態には自己参照、2ノードの循環、共有参照、receiver から到達不能なオブジェクトを置く。
操作の種類は8段階の周期で配置し、対象オブジェクト、フィールド、参照先、リテラルを固定 seed の疑似乱数で選ぶ。
全く制約のない操作列を生成しているわけではない。

- オブジェクト生成と、生成直後の constructor 既定値への初回書込み。
- 数値、文字列、真偽値のリテラル生成。数値に見える文字列も含める。
- 参照または値の追加と更新。同じフィールドへの再書込みも許す。
- 参照の削除による null 代入。
- オブジェクトまたはリテラルの戻り値指定と、その上書き。

全オブジェクトのクラス名、フィールドの有無、値、参照先 ID、戻り値を比較する。
null、undefined、欠落フィールドを区別し、receiver からの到達可能性で比較対象を絞らない。
最終状態だけでは途中の誤りが後続の上書きで隠れるため、操作列の全 prefix を比較する。
失敗時には seed、段階番号、再現用の request JSON を出す。

この検査は、単一クラス `Cell` と指定した constructor 既定値を使う。
生成器とグラフ実行器は、その既定値の定義を共有する。
任意の constructor の実行、テンプレート生成、hole 合成、生成 JS の実行までは、このテストの対象に含めない。
これらは別の結合テストが担当する。

## 合成メソッドの連続実行で確かめること

テスト実行時に `setAt`、`insert`、`append`、`prepend`、`popBack` をそれぞれ1回合成し、実演の全体検証を通過したコードを使う。
この5つの合成解を同じクラスへ配置し、参照側にも対応する5メソッドを配置する。
対象は、constructor の状態が共通する既存の `Obj` の整数リスト事例である。
生成側の参照メソッドは先に削除し、合成コードにメソッドが欠けていれば失敗させる。

入力条件は次のとおり。

- seed は1〜24、初期リスト長は1、2、8、32。
- 環境は先頭 receiver、共有された後続部分と切断オブジェクト、より大きいリスト内部の receiver の3種類。
- 各系列は50呼出し。メソッド、receiver の位置、有効な添字、値を疑似乱数で選ぶ。
- 値は -1000〜1000。リスト長と有効添字は各呼出し時の参照側の状態から求める。
- `insert` は指定位置の直後へ挿入する。`popBack` の receiver は後続ノードを持つものに限定する。
- 現在の先頭 receiver に `prepend` した場合は、戻った新しい先頭を次の receiver として使う。元の receiver への別名は保持する。

各呼出し後に、値だけでなく、全 own field、その有無と属性、オブジェクトのクラス、参照と共有関係、生成数、戻り値を比較する。
既存オブジェクトと生成オブジェクトには生成順に ID を付けるため、切断したノードへの余分な変更や、到達不能な余分な生成も検出する。
この比較方式は、生成順も参照実装と一致するという条件を置く。
呼出しで使わなかった根への別名も残し、途中の参照の付け替えを観測する。

失敗時には seed、初期値列、環境、段階番号、それまでの全呼出し履歴を出す。
Rust 側には合成コードを含む入力 payload も出す。
固定 seed のため、同じコードに対して同じ操作列を再実行できる。
自動的な反例縮小は行わない。

## 比較器が拒否する誤り

`tests/js/list-method-differential.test.cjs` は、次の候補を恒久的な回帰テストとして与える。

| 誤候補 | 検出対象 |
| --- | --- |
| 代入値に1を足す | 値の不一致 |
| 代入位置を1つずらす | 添字の不一致 |
| 同じ値のノードを複製して差し替える | 値列が同じでも異なる参照 |
| 不要な戻り値を返す | 戻り値の不一致 |
| 切断したノードの値を壊す | 到達可能なリストの外への変更 |
| 到達不能なノードを余分に生成する | 生成数の不一致 |
| null 代入の代わりにフィールドを削除する | フィールドの有無 |
| 対象メソッドを定義しない | 参照実装へのフォールバック防止 |
| 2回目の `setAt` だけ値を壊す | 連続実行中の不一致と再現情報 |

正例は5メソッドの単発比較と、5メソッドを混ぜた連続比較の計6件である。
誤候補は、プロセス起動の失敗や構文エラーを拒否成功とみなさず、比較 assertion による失敗を確認する。
比較器の VM 実行には10秒、比較器の自己検査から起動する子プロセスには15秒の上限を置く。

## 再現手順

既存の依存を準備したリポジトリのルートで実行する。

```sh
pnpm --dir external/escher-ts run build
cargo test --locked --test operation_graph_randomized_tests -- --nocapture
cargo test --locked --test whole_method_validation_tests adopted_methods_match_the_reference_after_each_seeded_random_call -- --nocapture
node --test tests/js/list-method-differential.test.cjs
cargo test --locked
cargo clippy --all-targets --all-features -- -D warnings
cargo fmt --check
git diff --check
```

合成テストは診断出力が多いため、ログに保存した場合は `random normalization:`、`random sequence comparison:`、`test result:` を検索する。
全テストは終了コードで失敗を通知する。

## 結果の説明範囲

2026-10-16 に、RefSyn `86872f9f868dd30e8e60b1d2d690fa63b696170a` に本テスト変更を加えた未コミットの作業状態で再実行した。
依存は Kanon `60fa5c8e80d05a28dd12438ee1f4876a49bba79f`、escher-ts `4e7c4bca45d98a0b5f2f76fd70486ed823c731f1`、Node.js v22.17.0 である。
escher-ts は実行前に再ビルドした。

| 実行 | 結果 |
| --- | --- |
| Rust 全体 | 59テスト成功。比較器を起動する1件を含む |
| 比較器の Node テスト | 15テスト成功。Rust の59件とは別枠であり、単純に加算しない |
| 正規化 | 3,072段階と空の操作列64件が一致。不整合な旧参照64件を拒否 |
| 5メソッドの混合呼出し | 288系列、14,400呼出しが各段階で一致 |
| 既存の単発比較 | 5メソッド、11,454入力が一致 |
| Clippy、fmt、diff の空白検査 | 成功 |

混合呼出しの内訳は `setAt` 3,243、`insert` 2,490、`append` 2,844、`prepend` 3,090、`popBack` 2,733である。
今回の実行ログは `/private/tmp/refsyn-random-final-cargo.log`、`/private/tmp/refsyn-random-comparator.log`、`/private/tmp/refsyn-random-clippy.log` に保存した。
これらは一時ファイルなので、消失した場合は上のコマンドで再実行する。
今回、GitHub Actions の結果確認と、runtime、web、Kanon の全テストの再実行は行っていない。

今回の検証は、固定 seed で生成した有限個の操作列についての一致と拒否を確認する。
試行数を合成成功率に読み替えることはできない。
学習用の実演をランダムに変えて合成性能を評価したものでもない。

既存の単発11,454入力の比較は残している。
それと今回の14,400呼出しは、独立入力の検査と、状態を引き継ぐ系列の検査という違いがあるため、単一のテスト件数にまとめない。

任意の長さや整数、空 receiver、範囲外の添字、1ノードでの `popBack` の一般的正しさは保証しない。
混合呼出しの比較は呼出しの前後を観測し、メソッド内部で一時的に行って元に戻した変更、ambient な globals や prototypes の変更は監視しない。
実演に対する反映前検証は別の `runtime/whole-method-validation.mjs` が担当する。
実際の Kanon の UI 操作やエディタ反映を自動再現した証拠でもない。
